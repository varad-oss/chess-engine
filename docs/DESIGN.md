# Design notes

This document explains how the engine is put together and, more importantly,
*why* each piece looks the way it does. Measured results live in
[RESULTS.md](RESULTS.md); the audit of the original version that motivated the
rewrite is in [AUDIT.md](AUDIT.md).

## Module map

```
src/core/      rules of chess, no engine policy        (depends on nothing)
  types.h        Square/Piece/Color, 16-bit Move, search value constants
  bitboard.*     bit tricks, attack tables, magic bitboards (+ magics.inc)
  position.*     board state, FEN, make/unmake, Zobrist, draws, SEE, gives_check
  movegen.*      strictly legal move generation (Noisy / Quiet / All), perft
  epd.*, rng.h   perft-suite parsing, deterministic PRNG
src/engine/    everything that makes it play            (depends on core)
  eval.*         tapered evaluation; eval_params.cpp is generated by the tuner
  tt.*           lockless shared transposition table
  search.*       Engine (thread control, time) + Worker (one search thread)
src/uci/       UCI protocol front end                   (depends on engine)
src/app/       CLI subcommands: bench, perft, datagen, openings, serve
tools/match/   match runner + SPRT                       (depends on core only)
tools/tune/    Texel tuner                               (depends on core + eval)
tests/         unit tests (minimal in-repo framework), UCI / HTTP / frontend integration tests
frontend/      single-file browser demo talking to `chess-engine serve`
```

Dependencies only point downwards. The match runner deliberately links only
the rules core: it adjudicates games between *any* two UCI engines, including
the original engine, which shares no code with this one.

## Board representation

Piece bitboards (6 by type, 2 by colour) plus a 64-entry mailbox. The mailbox
makes "what is on this square" O(1); the original engine scanned 12 bitboards
for it on every make/unmake and recomputed all occupancies from scratch.

Irreversible state (hash key, castling rights, en-passant square, fifty-move
counter, captured piece, checkers) lives in a `StateInfo` stack inside the
position, so `unmake_move` restores it by popping rather than recomputing.

**En-passant canonicalisation.** The ep square is only recorded (and hashed)
when an enemy pawn could actually capture. Otherwise 1.e4 and the same
position loaded from a FEN with `e3` would hash differently and transpositions
and repetitions would be missed. The original engine had exactly this
inconsistency (its incremental hash included a phantom "no ep" key that its
from-scratch hash did not).

**FEN parsing** validates instead of trusting: 8x8 board, exactly one king per
side, no pawns on the back ranks, consistent ep square, numeric counters (now
optional), and the side not to move must not be in check. Parsing goes into a
temporary, so a bad FEN leaves the previous position intact. The original
crashed (uncaught `std::invalid_argument`) on a FEN without move counters.

## Move generation: strictly legal

The original generated pseudo-legal moves and filtered each with make/
is-king-attacked/unmake. This generator produces only legal moves:

1. Compute checkers (cached in `StateInfo`) and pinned pieces (`king_blockers`).
2. King moves: target squares are tested with the king *removed* from the
   occupancy, so stepping back along a checking ray is correctly illegal.
3. Double check: stop after king moves.
4. Single check: all other moves must land on `between(king, checker) | checker`.
5. Pinned pieces may only move along `line(king, piece)`.
6. En passant removes two pieces from one rank, which can expose the king
   horizontally; it is verified by recomputing attacks on the king after the
   capture.

Generation is split into **Noisy** (captures and queen promotions) and
**Quiet** (everything else) so quiescence search can generate captures only.
A unit test checks on thousands of positions that Noisy and Quiet partition
All exactly.

Legal generation also allows *bulk counting* in perft (count the last ply
without making the moves). Like-for-like (making every leaf move), perft is
2.4–3x faster than the original; with bulk counting, 15–17x
([RESULTS.md](RESULTS.md)).

**Magic bitboards.** The multipliers are embedded but verified at startup:
each square's table is filled from ray-walked reference attacks and any
destructive collision rejects the multiplier and triggers a fixed-seed
search. (An earlier version of this rewrite searched at every start; that
cost up to 3 s of startup time on a loaded machine and was replaced.)

## Search

`Engine` owns the transposition table, the worker threads and time control;
`Worker` is one search thread with its own position copy and move-ordering
statistics. `Engine::start` returns immediately and the search reports through
callbacks, which is what lets the UCI loop keep reading `stop`/`isready`/`quit`.
The original ran the search on the input thread, so `stop` was ignored and
`go infinite` never returned.

Per node (`Worker::search`), in order:

| step | purpose |
| --- | --- |
| check extension | never enter quiescence while in check |
| draw detection | repetition (2-fold inside the tree, 3-fold across game history), 50-move rule with mate taking precedence, insufficient material |
| mate distance pruning | no line can beat a mate already found closer to the root |
| TT probe | cutoffs at non-PV nodes only; mate scores stored node-relative |
| static eval | from the TT when available, refined by a TT bound |
| reverse futility pruning | depth <= 7, eval far above beta |
| null-move pruning | R = 3 + depth/4 + ..., never twice in a row, never without non-pawn material (zugzwang) |
| internal iterative reduction | depth >= 4 without a hash move |
| move loop | legal moves scored once, then picked best-first |
| shallow pruning | quiet non-checking moves: late-move, futility and SEE pruning; checks and captures: only SEE pruning (losing more than 100·depth cp); nothing when every move so far loses to mate |
| PVS + LMR | first move full window; others null-window, reduced by a log(depth)·log(move#) table; a reduced fail-high is re-searched at full depth and then with the full window at PV nodes |
| history/killers | quiet cutoffs update a butterfly history with gravity (bounded) and two killers per ply |

Move ordering: TT move > captures with SEE >= 0 by MVV-LVA > killers >
quiets by history > losing captures.

Quiescence search stands pat when not in check, searches only captures that
do not lose material by SEE, and searches **all evasions** when in check
(the original stood pat in check, so it could miss mates at the horizon).

Iterative deepening uses aspiration windows from depth 5, widening by 1.5x on
each fail. If time runs out mid-iteration, a root move that completed and
raised alpha in that iteration is preferred over the previous iteration's move.

### Bugs in the original search that the design addresses

* LMR fail-highs were not re-searched at full depth; a reduced search alone
  decided the cutoff.
* Null-move pruning was used in pawn endgames and twice in a row.
* `killer_moves[2][64]` was indexed by ply with unbounded check extensions:
  out-of-bounds writes in long checking sequences.
* History scores were unbounded and could outrank captures and killers.
* Mate scores were printed as `mate --1`.

## Transposition table: lockless and data-race-free

Entries are two 64-bit words: `key ^ data` and `data`, where `data` packs the
move, score, static eval, depth, bound and a 6-bit generation. A reader
accepts an entry only if `check ^ data == key`, so a torn read (two writers
interleaving) is detected and treated as a miss (Hyatt & Mann's XOR trick).

Both words are `std::atomic<uint64_t>` accessed with `memory_order_relaxed`.
This matters: the classic implementation uses plain memory and is a data race,
i.e. undefined behaviour in C++. Relaxed atomics compile to ordinary loads and
stores on x86-64 and ARM64, so the cost is zero, and ThreadSanitizer stays
silent on the 4-thread search (`make sanitize`).

Buckets hold four entries in one 64-byte cache line. Replacement keeps the
deepest result for the same position from the current search; otherwise it
evicts the entry with the lowest `depth - 8 * age`.

## Multi-threading: Lazy SMP

Threads search the same root independently and share information only
through the TT; odd helper threads skip every other depth to diversify. This
is the scheme used by most modern engines because it scales reasonably
with almost no synchronisation. The main thread owns time control and
reporting; when it finishes, it stops the helpers.

## Evaluation and tuning

The evaluation is a classical tapered evaluation: material, piece-square
tables, mobility (safe squares, excluding squares attacked by enemy pawns),
pawn structure (passed, isolated, doubled, connected), bishop pair, rooks on
(semi-)open files, king pawn shield, attacks near the enemy king, pawn threats
and a tempo bonus. Each term is an (mg, eg) pair blended by game phase.

Two properties are enforced by tests:

* **Colour symmetry**: evaluating a position and its colour-flipped mirror must
  give the same score. The original's trapped-bishop rule failed this (it
  penalised Black for a normal Ba7).
* **Linearity**: `eval::trace` returns feature counts such that the evaluation
  equals `sum(count_i * weight_i)` interpolated by phase, exactly as computed
  by the tuner. The tuner therefore optimises the real evaluation, not an
  approximation of it.

The tuner writes weights in a canonical form. Material, the mean of each
piece-square table and the mean of each mobility table each add exactly one
term per piece, so only their sum is determined by the data. The tuner moves
the table means into the material value with integer shifts, which evaluate
every position identically (the bench node count is unchanged), so the
numbers in `eval_params.cpp` can be read directly.

The weights in `eval_params.cpp` are produced by the pipeline:

```
chess-engine datagen  ->  self-play games at a fixed node count, quiet positions
                          labelled with the game result (deterministic per seed)
tune                  ->  Texel's method: fit K, then Adam on the mean squared
                          error between result and sigmoid(K * eval); keep the
                          weights of the best epoch on a held-out split
match --sprt          ->  accept the new weights only if they gain Elo
```

## Verification strategy

| what | how |
| --- | --- |
| move generation | perft against 21 published positions to full recorded depth (640M leaf nodes), including the ep-pin, castling-through-check and promotion edge cases |
| magic tables | random-occupancy cross-check against ray walking (128k queries) |
| make/unmake | random walks: after every move the incremental hash equals a from-scratch hash, mailbox and bitboards agree, and unmaking restores the exact FEN |
| `gives_check` | property test against make-move-then-test over all legal moves of 400 positions |
| evaluation | colour symmetry, trace/eval equality |
| search | mate-in-N, mated-in-N, stalemate, forced moves, node-limit exactness, determinism, `searchmoves` |
| protocol | Python integration tests drive the real binary: `stop`/`isready` during search, `movetime` and clock adherence, malformed input, `quit` mid-search |
| memory/UB/races | the unit tests and a bench under ASan+UBSan and under TSan |
| HTTP server | integration tests: legality, repetition from move history, size limit (413), CORS policy, think-time clamp |
| statistics | Elo/LLR formulas unit-tested against hand calculations |
| strength | the match runner (pentanomial statistics, SPRT) |
| search changes | `bench` node count as a functional fingerprint: refactors must keep it identical |
